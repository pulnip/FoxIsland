# Voxel Animal Platformer — Development Plan

A small Unity 3D game: a voxel animal walks and jumps around small tile maps (levels) viewed from a
quarter (isometric) camera, collecting randomly placed items. Falling off ends the game;
collecting every item clears it. Either way, the player can restart.

This file is the source of truth for implementation.

## 3. Character pipeline (Blender Python)

### 3.1 Script contract

Blender 5.2 LTS, headless (`blender.exe` in `C:\Program Files\Blender Foundation\Blender 5.2\`):

```
blender --background --factory-startup --python Tools/Blender/generate_character.py -- \
    --animal fox --out Unity/Assets/Art/Character/Fox.fbx [--preview DIR] [--blend PATH]
```

The script:

1. Resets to an empty factory scene at 30 fps.
2. Loads `animals/<name>.py` (see §3.2).
3. Builds one mesh object `Mesh_<Part>` **per body part**. A face is emitted only when the
   neighbouring voxel of the *same part* is empty; faces against other parts stay, because
   they show when parts rotate. One material per palette entry used by the part.
4. Builds the armature `Fox`: `Root → Body → {Head, LegFL, LegFR, LegBL, LegBR, Tail}`.
   Each bone's head sits at the part's pivot and points up (+Z, roll 0), so bone X pitches
   (+ swings a leg back, dips the head, raises the tail), bone Y yaws, bone Z rolls.
   Each part mesh is parented to its bone (`parent_type = 'BONE'`) keeping its world placement:
   rigid parts, no skinning, plain `MeshRenderer`s in Unity.
5. Keys five actions, every bone on every key (so clips never inherit each other's pose):
   `Idle` (30 f loop: body bob, head nod, tail sway), `Walk` (16 f loop: diagonal leg pairs
   ±25°; at each stride extreme the body rolls ±4° and twists ±3° with the weight shift while
   the head counters by ∓2° and the tail swings against the twist; body bob ×2 at the passing
   poses), `Run` (12 f loop, bound gait: front legs together, back legs together;
   stretch in the air → front feet land, nose dips → legs gather under the body → back feet
   push off, nose rises; the head takes back half the body pitch, the tail trails),
   `Jump` (9 f one-shot: front legs forward, back legs back,
   nose up, tail up), `Fall` (12 f loop: legs spread, nose down, tail up, slight flutter).
6. Exports FBX with `bake_anim_use_all_actions=True`, `add_leaf_bones=False`,
   `apply_scale_options='FBX_SCALE_ALL'`, `axis_forward='-Z'`, `axis_up='Y'`,
   `armature_nodetype='NULL'`. Take names come out as `Fox|<Action>`; M7 renames the
   Unity clips to `Idle`, `Walk`, `Run`, `Jump`, `Fall`.
7. `--preview DIR` renders one Workbench still per clip (flat palette colors, cavity, outline;
   `Raw` view transform because Unity reads the palette as sRGB). `--blend PATH` saves the scene.

### 3.2 Voxel data format

```python
VOXEL_SIZE = 0.05   # fox: 6 wide, 19 long, 12 tall voxels -> 0.3 x 0.95 x 0.6 units

PALETTE = {"o": (0.93, 0.47, 0.13), "w": (0.97, 0.95, 0.90), "k": (0.10, 0.08, 0.08)}

PARTS = {
    "Head": {
        "parent": "Body",
        "pivot": (0, -3, 6),                        # voxel-boundary coordinates
        "boxes": [
            ("o", (-3, -8, 5), (2, -4, 9)),         # inclusive voxel index ranges
            ("k", (-2, -8, 7), (-2, -8, 7)),        # later boxes paint over earlier ones
            ...
        ],
    },
    ...
}
```

Axes are Blender's: +X is the animal's left, the nose points to −Y, +Z is up, z = 0 is the
ground. Adding a new animal = adding one file under `animals/` with the same part names.

### 3.3 Acceptance

- Script runs headless with exit code 0 on Blender 5.2.
- Re-importing the FBX in Blender shows 7 part meshes parented to their bones, 8 bones,
  5 actions with the right lengths, 3 materials.
- FBX imports into Unity without warnings as a Generic rig facing +Z, feet at y ≈ 0.

### 3.4 Unity import (`CharacterAssetBuilder`, `CharacterMaterialPostprocessor`)

- Generic rig, avatar from this model, no cameras/lights/blend shapes/visibility.
- **Bake Axis Conversion stays off.** With it on, the rest pose is fixed but the clips' root
  curves are not, and the animated fox tips over 90°. Off, the model root keeps Blender's
  −90° X rotation and everything agrees; Blender −Y maps to Unity +Z.
- Clips renamed from `Fox|Idle` to `Idle` etc.; Idle, Walk, Run, Fall loop, Jump does not.
- `CharacterMaterialPostprocessor` imports every material under `Assets/Art/Character/` as URP
  Lit with the FBX diffuse color unchanged (read as sRGB, like the tile palette), smoothness
  0.1, metallic 0. URP's default FBX conversion washed the palette out.

## 4. Map

### 4.1 Cells

Every cell is a hole or a block. A block has three independent properties (`CellSpec`):

| Property | Values | Effect |
| -------- | ------ | ------ |
| Height | 0–6 | Top surface at `height × 0.5` (§4.4). |
| Skin | sand `s`, meadow `m`, forest `f`, rock `r`, snow `n`, ice `i`, water `w`, iceberg `b` | Materials, decorations, and footing (§4.9). Ice and iceberg are slippery; snow takes prints; an iceberg floats, so it must be height 0. |
| Crumbling | flag `c` | The first landing starts it: it shakes for 0.8 s (the warning, ramping from 30% to full strength), then sinks into the lake in a burst of `CrumbleDust`, splashing (`TileSplash`) as its top goes under; it respawns 3 s after dropping, waiting while anything occupies its cell. Cracks mark it. |

A hole (`.`) is lake water: falling in ends the game. The **start** is not a cell kind but a
separate cell reference on the layout (`MapLayout.Start`); it must be a block and never holds an
item. Crumbling blocks respawn so that no item can become permanently unreachable.

live in the assets; tune them with the map tool.

### 4.3 Data

- `MapLayout` (one asset per level under `Assets/ScriptableObjects/Levels/`) stores the cells as
  text rows (first row = farthest from the camera, tokens separated by spaces), 2–8 per side
  (`MinSize`, `MaxSize`). A token is `.` for a hole or `<height><skin>[c]`, e.g. `0s`, `2m`,
  `5i`, `0mc` (`CellSpec.TryParse` / `ToToken`). Plus `_start` (cell), the items, and the
  puzzle elements (§4.10: `Tide`, `Switches`, `RisingBlocks`, `Crates`, `Springboards`,
  `Platforms`). `MaxHeight` includes raised blocks and platforms.
  Parsing checks only the shape (tokens, rectangular rows), so a layout mid-edit still loads;
  content rules live in `MapLayoutValidator` (§4.8), whose errors `OnValidate` logs.
  `SetCells` writes rows back; `MaxHeight` frames the camera.
- Items per layout: `ItemMode` `Random` (`RandomItemCount`, default 4) or `Fixed` (`Items`:
  `ItemPlacement` = cell + `InAir`).
- `WorldList` (`Assets/ScriptableObjects/WorldList.asset`): the worlds in play order; each
  `World` has a name, an accent color (stage list, map tool), and its stages (layouts) in order.
  A `StageRef` (world, index) names a stage; its label is `w-s`, 1-based (`1-3`). `TryGetNext`
  walks to the next stage, skipping empty worlds. A world may stay empty until its stages exist.
- `LevelLoader` (§8) picks the layout at scene load and calls `MapBuilder.Build(layout)`;
  `MapBuilder` keeps a cell → tile lookup (`TryGetTile`). Blocks use `Tile_Solid` or, when
  crumbling, `Tile_Crumbling`; `MapBuilder._skins` (`SkinMaterials[]`, set by `MainSceneSetup`
  from `MapAssetBuilder.SkinMaterialPaths`) gives each skin's slab and pillar materials.
- Older layouts (digit / `C` / `S` tokens, height-based looks) are rewritten once by
  `LegacyLayoutConverter` during Build All: `0`–`2` → meadow, `3`–`4` → forest, `5`–`6` → snow,
  `5i`/`6i` stay ice, `C` → `0sc`, `S` → `0m` + start.

### 4.4 Coordinates

- Tiles are `TileSize = 1.5` units wide and deep (height per level stays 0.5).
  Tile `(column, row)` is centered at world `(column × 1.5, *, row × 1.5)`; a 4×4 map spans
  x, z ∈ [-0.75, 5.25]. Row 0 / column 0 is the corner nearest the camera.
- A block's top surface is at `y = height × 0.5`. Its collider is a block down to `y = -0.5`
  (`TileBottom`); its visual is a pillar down to the lake bed at `y = -1.5` (`LakeBedY`), so
  blocks stand in the water (§4.7). The top 0.15 is a slab in the skin's top material, the rest
  the skin's body material.
- Prefab hierarchy: `Root (Tile, BoxCollider[, CrumblingTile]) → Visual → Top, Body`. Grass,
  decorations, and snow go under `Tile.Visual`, so they shake and sink with a crumbling block.
  `CrumblingTile` moves only `Visual`; the collider stays put and is disabled while the tile
  is gone. The player notifies it from `OnControllerColliderHit` on an upward-facing hit.
- The collider covers the full cell; visuals are inset by 0.04 so the grid reads clearly.
- The camera frames `MapMetrics.FramedBounds(width, depth, maxHeight, jumpHeight)`: `GridBounds`
  (tile bottoms to the top of the layout's highest block, `MapLayout.MaxHeight`) raised by the
  player's jump height. `LevelLoader` sets it per level at runtime; `MainSceneSetup` sets it for
  level 1 so the scene reads right in edit mode. For the 4×4 level 1 (max level 2): center
  `(2.25, 0.85, 2.25)`, size `(6, 2.7, 6)`.

### 4.5 Physics tuning targets

- Run speed 3 units/s by default; walk speed 1 unit/s in walk mode (Left Ctrl toggles). Wading in
  shallow water multiplies either by 0.6 (§4.9).
- Jump apex: ~1.2 units above takeoff → can climb one level (0.5) comfortably, two levels (1.0) barely.
- Horizontal jump reach (air time ≈ 0.62 s): walking ≈ 0.62, running ≈ 1.86 units. A one-tile
  hole is 1.5 units edge to edge (the center has to travel ≈ 1.1–1.5 with the 0.2 radius), so
  crossing a hole takes a running jump.
- Gravity: ~-25 units/s² for snappy feel.
- Ice and icebergs (§4.9): standing on them, the horizontal velocity moves toward the input at 3 units/s²
  (`_iceAcceleration`) and dies down at 2 units/s² with no input (`_iceDeceleration`); a full-speed
  run takes 1 s to reach and slides 2.25 units after letting go. A jump from ice keeps that
  momentum until landing. Hitting a wall takes the controller's actual velocity, so a slide
  stops against it. Elsewhere velocity follows the input instantly.

### 4.6 Grass

- `GrassField` (on the `Map` object, builds in `Start` after `LevelLoader.Awake`) scatters voxel
  grass on **meadow** blocks that do not crumble. Decoration only: no colliders. Forest blocks
  get 1–3 short dark tufts: material `Grass_Subalpine` (same shader, darker), height scaled ×0.7;
  they sway and flatten too.
- Each meadow block gets one coverage: **Bare** (no grass), **Sparse** (3–5 tufts at least 0.3
  apart, kept 0.2 from the edge), or **Full** (a 4×4 grid over the tile with ±30% jitter and a
  10% chance to skip a cell). Tiles are split by share, not rolled one by one, so every build
  mixes all three: 25% bare, 35% full, the rest sparse, assigned by a seeded shuffle.
  Positions are seeded per tile coordinate, so the field is identical every run (current
  layout: 2 bare, 3 sparse, 3 full, 58 tufts). Tufts are children of their tile, at the tile
  top, with a random yaw.
- A tuft is one of 4 code-built meshes: 7–11 axis-aligned blades, 0.045 wide, 0.12–0.2 tall
  (up to the fox's body, whose underside is at 0.15). Every vertex carries its blade's random
  phase in `uv0.x` and its blade base (x, z, object space) in `uv1`; mesh bounds are padded by
  0.2 for the bend. Material `Grass_Blade` uses `Assets/Art/Shaders/Grass.shader`
  (`MyGame/Grass`; brighter than the tile grass so it reads at camera distance); no shadow
  casting. Tufts themselves never move: **each blade bends in the vertex shader**, rotating
  rigidly about its own base (normals rotated too).
- Wind (`_GrassWind`): each blade leans downwind by 0–7°, driven by two sines whose phase
  follows the blade base along the wind direction (gusts travel across the map) plus its
  random phase (neighbouring blades differ). Wind (1, 0, 0.4), 1.1 Hz, wavelength 3 units.
- Trampling (`_GrassTrample[16]`, `_trampler` = the Player): `GrassField` records the player's
  position every `recoverTime / 16` s into a ring and sends each sample with strength
  `1 − age / 0.6 s`, plus the current position at strength 1. Per blade the shader takes the
  strongest `saturate(1 − distance / 0.4) × strength` among samples within 0.3 vertically,
  and leans away from that sample by up to 65° (smoothstepped) while the wind lean fades.
  So grass flattens under the fox and stands back up over 0.6 s behind it, with no per-blade
  state on the CPU. `TrailLength` in `GrassField` must match `GRASS_TRAIL_LENGTH` in the shader.
- The shader has ForwardLit (main light, soft shadows, SH ambient), DepthOnly, and
  DepthNormals passes that share the same bend, so SSAO follows the bent blades.
- `MainSceneSetup` resets `GrassField` to its code defaults on every build, so tune it by
  changing the defaults in `GrassField.cs` (inspector changes are for trying values out).

### 4.7 Water

- The grid stands in a lake: the holes and everything around the grid are water at
  `MapMetrics.WaterLevel = -0.3` (level-0 tiles rise 0.3 above it). Touching it is game over (§8).
- `Lake` (scene object, built by `MainSceneSetup`; `LevelLoader` centers it on each level's grid): `WaterSurface`
  builds a flat 60 × 60 grid mesh (0.5 cells) in `Awake`, play mode only, like the grass;
  `Bed` is a sand cube whose top is at `LakeBedY = -1.5`. The camera background is the deep
  water color in case the edge ever shows. Tall maps make the camera see farther across the
  lake, so `QuarterViewCamera` pushes its far plane out by `orthographicSize / tan(pitch)`.
- Material `Water` uses `Assets/Art/Shaders/Water.shader` (`MyGame/Water`, transparent, no
  depth write, receives shadows). `MapAssetBuilder` sets its properties explicitly:
  - Waves: three travelling sines (wavelengths 2.5, ×0.63, ×0.41; height 0.02 and smaller;
    0.4 units/s) move the vertices; the fragment recomputes the slope, adds two small ripples,
    and exaggerates it ×3 for the normal.
  - Depth: the camera depth texture (forced on for the main camera) gives the water depth
    behind each pixel, measured vertically. Color and opacity blend from shallow
    (0.36, 0.78, 0.80, α 0.45) to deep (0.12, 0.38, 0.62, α 0.92) over 0.8 units, so the
    pillars show just under the surface and fade out below.
  - Foam: a crisp band where the depth is under 0.06 (wobbling ±50%), plus a thinner band
    drifting from the shore out to 4× that width every ~3 s.
- Splashes: `Splash` (22 pale cubes up from a cone) where the fox touches the water;
  `TileSplash` (36 cubes up from a tile-sized flat box) when a crumbling tile's top goes under.

### 4.8 Map tool

`Tools/MyGame/Map Tool` (`Editor/MapTool/MapToolWindow`, IMGUI) edits `WorldList` and the
layouts.

- **Drafts**: each opened layout is edited as an in-memory copy (`Instantiate`, `DontSave`);
  painting, undo (`Undo.RecordObject` on the draft), checks, the preview, and test play all use
  the draft. The asset changes only on **Save** (button or Ctrl+S; `MapLayout.CopyFrom`).
  **Discard Changes** (with a confirmation) copies the asset back and clears the draft's undo.
  A level whose draft differs from its asset (compared as JSON) shows `*` in the list and the
  name field; the window sets `hasUnsavedChanges`, so closing it asks Save / Discard / Cancel
  for all of them. Drafts switch with the selection and keep their edits. A script reload
  stashes unsaved drafts in `SessionState` and restores them. When the window regains focus,
  clean drafts reload from their assets (so a `git checkout` shows up). Stage list operations
  (order, New, Duplicate, Remove, rename) still apply to the assets at once; Duplicate copies
  what is on screen, unsaved edits included.

- **Stage lists** (left): one reorderable list per world (header with the world's color bar,
  rows `w-s  name`); dragging reorders within a world. New (blank 4×4 meadow at height 0, start
  at (0, 0), `Levels/<World>NN.asset`, added at the end of the selected world), Duplicate (copy
  inserted after the selection), Remove (from the world, or also move the asset to the trash
  after a confirmation; the game keeps at least one stage), "Move to <World>" (appends the stage
  to another world). Name field renames the asset, which also drops its saved clear (§8.2).
  The selection survives script reloads (`SessionState`).
- **Grid** (top-down): row 0 at the bottom (camera side), column 0 on the left, axis numbers
  match the check messages. Cell color = skin (lighter the higher), label = height plus `c` when
  crumbling, a blue `S` badge on the start; `◆` / `◆ ↑` = fixed item on the ground / in the air.
- **Brushes** (left-drag paints), in rows that never touch each other's property:
  - Height: `H` Hole, `0`–`6`. A height brush on a hole makes a block of the last used skin.
  - Skin (Shift + letter of the token): `⇧S` Sand, `⇧M` Meadow, `⇧F` Forest, `⇧R` Rock, `⇧N`
    Snow, `⇧I` Ice, `⇧W` Water, `⇧B` Iceberg. A skin brush on a hole makes a height-0 block.
  - Other: `C` Crumbling, `V` Firm (clears crumbling), `T` Start (moves the start; blocks only),
    `G` Item, `A` Item (air), `E` Erase (the item and every puzzle element on the cell, and
    platforms ending there). An item on a cell that can no longer hold one is removed. Item
    brushes work only on firm, still blocks other than the start, a rising block, or a crate,
    and switch the layout to `Fixed`.
  - Puzzle (§4.10): `K` Switch, `U` Rising, `X` Crate, `J` Spring, `P` Platform. Options row:
    group A/B/C (`Q` cycles) for switches and rising blocks, switch timer (0–10 s in 0.5 s
    steps), "Rise to" (0–6), platform height (0–6) and period (3–12 s). Switch, crate, and springboard share a cell slot (placing one
    replaces the others); all need a firm block, crates and springboards stay off the start.
    Platform: click one end, then the other in the same row or column (`Esc` cancels). Painting
    a hole, crumbling, or iceberg drops the cell's puzzle elements.
  - Grid badges: rising block = inner outline in its group color + `↑n`/`↓n` (top right);
    switch = group letter plus its timer (`A4`), crate `▣`, springboard `⤒` (bottom left); `≈` (bottom right) = under
    water at high tide; platforms = a bar along the path with `P<height>` at both ends.
- **Size**: width × depth (2–8), grown or cropped from the (0, 0) corner (new cells height 0 in
  the last used skin);
  Shift ◀▶▲▼ moves everything one cell with wrap-around.
- **Items**: mode popup; `Random` count slider (0–32), or `Fixed` with a count and Clear Items.
- **Tide**: toggle, rise (0.3–1.0) and period (6–12 s) sliders.
- **Checks** (`MapLayoutValidator.Validate` → `LayoutReport`: issues + per-cell `Reachability`),
  rerun on every edit; clicking an issue outlines its cell.
  - Errors: rows do not parse, size outside 2–8, start not on a block, an iceberg above height 0,
    fixed item on a cell that cannot hold one (hole, crumbling, iceberg, start, rising block,
    crate) or two on one cell, no items; a switch, rising block, crate, or springboard off a firm
    block, two in one slot, a switch or springboard on a rising block, a crate or springboard on
    the start; a platform leaving the grid or not along one row or column. Play This Level is
    disabled while there are errors.
  - Warnings: more random items than cells that can hold one, random items able to land on
    unreachable cells, unreachable blocks (red outline) and fixed items, blocks that need a
    two-level jump (orange outline); a rising block whose group has no switch (or that rises to
    its own height), a switch whose group has nothing to move, a platform passing through a
    block at or above its height; blocks under water at high tide (one summary, `≈` on the grid)
    and a start that floods.
  - Reachability (approximate, §4.5): breadth-first from the start over blocks, 4-neighbour
    moves: up one level is easy, up two is "hard" (still counted), any drop is fine; a running
    jump crosses one hole in a straight line onto a block no higher than the takeoff. Air items
    count as reachable with their block (jump apex 1.2). Each cell offers a set of floor heights:
    its block, a rising block's raised height, the top of a crate on each cell it can slide to
    along its row or column (over floors no higher than its own), a hole that crate would fill
    (height 0), and a platform passing over (so holes on a platform path or in a crate's line
    become standable; reachability warnings cover real blocks only). A step works when some
    height of the next cell is close enough above some height of this one. From a springboard
    the climb limit is 4 (also across a hole); a platform joins every cell on its path. The tide
    is judged at low water. Moving elements are only estimated; the tool says so.
- **3D Preview in Scene View** (`MapToolPreview`): a `[Map Preview]` root in the Main scene with
  its own `MapBuilder`, `GrassField`, `TerrainDecor`, `SnowField`, and `WaterSurface` copied from the scene's, rebuilt on every
  edit and framed in the Scene view. Every object in it is `HideFlags.DontSave`, so saving the
  scene never writes it. Cleared when the window closes, the toggle goes off, or play mode starts.
- **▶ Play This Level** (`MapToolPlayMode`): opens the Main scene, stores the draft as JSON in
  `SessionState` (`LevelSession.TestLayoutKey`; unsaved edits play too, nothing is saved), and
  enters play mode. `LevelSession.TestLayout` rebuilds a layout from it for `LevelLoader`, the
  title is skipped, and the HUD shows `TEST PLAY`; the key is erased when play mode ends.
- `MapLayout` resets its parse cache in `OnAfterDeserialize`, so undo and JSON overwrites never
  leave stale cells behind.

### 4.10 Puzzle elements

Built by `PuzzleBoard` (the `Puzzles` object; `LevelLoader` calls `Build(layout)` right after
`MapBuilder.Build`) from the layout's lists, with prefabs from `PuzzleAssetBuilder` (cubes,
`Puzzle_*` materials). The map tool preview builds them too, at rest. Each world introduces one:

| Element | Data | Behavior |
|---|---|---|
| Tide (beach) | `TideSettings`: enabled, rise 0.3–1.0, period 6–12 s | `Tide` (on `Lake`) moves the water to `WaterLevel + rise × (1 − cos 2πt/T) / 2`, starting at low tide; the clock runs only outside the title. `GameManager.WaterLevel` follows it, so low blocks drown the fox at high tide. Icebergs ride it (`MapBuilder._tide` → `FloatingBlock.Tide`). HUD gauge (§8.1). |
| Switch (meadow) | `SwitchPlacement`: cell, group A/B/C, hold time 0–10 s | `FloorSwitch`: a plate on the block top, no collider. Pressed while a `CharacterController` is over it or a crate rests on its cell; the button sinks 0.05. A timer switch (hold time > 0) stays on that long after release, its button rising back as the time runs out; 0 = only while pressed. A group is on while any of its switches is on (`PuzzleBoard.IsGroupOn`). Meadow stages use timers (the fox alone), forest ones hold with crates. |
| Rising block (meadow) | `RisingBlockPlacement`: cell, group, raised height 0–6 | `RisingBlock` on the cell's tile moves it between its own height and the raised height (lower = it sinks) in 0.4 s while the group is on. Pillar and collider stretch down so it always reaches the lake bed. A frame in the group color (`RisingMarker`) marks the top. |
| Crate (forest) | `Crates`: starting cells | `Crate`, one level tall, pivot at the bottom. Walking into a side along a grid axis (from its floor level) for 0.2 s slides it one cell in 0.25 s, if the target is inside the grid, no higher, not a crumbling block, iceberg, springboard, or other crate, and the fox is not in the way. It drops to a lower floor, keeps sliding over ice, and falling into a hole makes it a permanent height-0 floor (top flush at 0; splash). Resting crates follow the block under them (rising blocks) and press switches. |
| Springboard (mountain) | `Springboards`: cells | `Springboard`: pad on the block top, no collider. A grounded fox over it is launched 2.4 high (`PlayerController.Launch`, raises `Jumped`), enough for four levels; 0.3 s cooldown, the pad wobbles. |
| Moving platform (mountain) | `PlatformPlacement`: from, to (same row or column), height 0–6, period 3–12 s | `MovingPlatform`: a 1.44 × 0.3 slab whose top is the floor height, shuttling between the two cells with smoothstep easing and a 20% pause at each end. |

- `PlayerController` rides whatever it stands on: it remembers the collider's transform under
  its feet and, before moving, adds that transform's movement since the last frame to its own
  position, then calls `Physics.SyncTransforms()` (auto sync is off) so the move sees colliders
  where they are now. Movers run earlier (`[DefaultExecutionOrder]` −40 tide, −30 board and
  switches, −20 rising blocks, platforms, springboards, −15 crates).
- Group colors (`PuzzleGroups.ColorOf`): A pink-red, B blue, C violet.

### 4.9 Skins

A block's look and footing come from its skin, not its height. The worlds lean on the skins
(beach sand and water, meadow, forest floor, mountain rock, snow, and ice), after real
altitudinal zonation (subalpine conifer forest over dwarf rhododendron and bilberry, creeping
dwarf pine at the treeline, alpine moss and cushion plants, nival snow). No trees are placed:
everything sits under 0.2 so the fox and gems stay visible.

| Skin | Top / sides | Decorations (`TerrainDecor` unless noted) | Footing |
|---|---|---|---|
| Sand `s` | `Tile_Sand` / `Tile_Sandstone` | shells, pebbles, driftwood | normal |
| Meadow `m` | `Tile_Grass` / `Tile_Dirt` | grass (`GrassField`, §4.6) | normal |
| Forest `f` | `Tile_Subalpine` / `Tile_DarkEarth` | dwarf shrubs with berries, needle litter, krummholz mats, a rock; short dark grass (`GrassField`) | normal |
| Rock `r` | `Tile_RockTop` / `Tile_Rock` | stones, moss | normal |
| Snow `n` | `Tile_Snow` + snow layer / `Tile_Rock` | moss and lichen, cushion plants, rocks, wind ridges | prints press in |
| Ice `i` | `Tile_Ice` / `Tile_Rock` | none | slippery |
| Water `w` | `Tile_WaterBed` / `Tile_Sandstone` | sandstone rim + pool water surface | wading: speed ×0.6, a small splash per step, no prints |
| Iceberg `b` | `Tile_Ice` / `Tile_IcebergBody` | none | slippery; floats, bobs, and sinks underfoot; height 0 only |

Crumbling blocks of any skin show only dark cracks.

- **Shallow water** (`w`): `TerrainDecor` puts a sandstone rim `MapMetrics.PoolDepth = 0.15` high
  around the block (visual only) and a 6 × 6 water surface just under it, drawn with
  `Water_Pool` (the lake's `MyGame/Water` shader with foam width 0.025 and waves 0.008, so the
  drifting foam band stays shallower than the pool). The fox stands on the block top, ankle-deep.
  `PlayerController.IsWading` multiplies speed by `_waterSpeedFactor = 0.6`; each footstep
  spawns `StepSplash` (6 droplets) at the surface instead of a print. Only the lake ends the game.
- **Iceberg** (`b`): `MapBuilder` adds `FloatingBlock`, and `Tile` cuts its pillar off at
  `MapMetrics.IcebergBottom = -0.9`, so it floats. The whole tile (collider included) bobs ±0.03
  over 3 s with a 1.5° rock, phase by cell; while a `CharacterController` stands on it, it sinks
  toward 0.12 at 0.35 units/s and rises again when free. Slippery like ice (§4.5).
- Footprint particles take the ground's tint: darker sand on sand, gray on rock, the default
  dark earth elsewhere (`FootprintEmitter`).

- `TerrainDecor` (on `Map`, builds in `Start`): code-built voxel meshes (4 variants per kind,
  `VoxelMeshBuilder`, vertex colors converted to linear) on one material `Decor_Voxel`
  (`Assets/Art/Shaders/VoxelLit.shader`, `MyGame/VoxelLit`: vertex color × main light with
  shadows + SH; ForwardLit, DepthOnly, DepthNormals; no shadow casting). Seeded per tile, kept
  0.2 from the tile edge and 0.28 apart.
- Snow (`SnowField`, on `Map`): every snow tile gets a slab `MapMetrics.SnowDepth = 0.08` thick
  on top (16 × 16 top grid, sides attached); the fox stands on the collider at the tile top, so its
  feet sink into the snow. One map-wide track texture (R8, 512², the grid bounds + 0.5) holds how
  far the snow is pressed; `Stamp(position, size, yaw, depth)` writes a soft ellipse on the CPU
  (deeper value wins) and uploads in `LateUpdate` when changed. Prints stay for the level.
  Material `Snow` (`Assets/Art/Shaders/Snow.shader`, `MyGame/Snow`): vertices marked in vertex
  color R sink by up to 0.065; top-face vertices (G) take their normal from the texture slope;
  pressed snow is tinted blue. Globals `_SnowTracks`, `_SnowTrackRect`, `_SnowTrackTexel`.
- Footprints on snow: `FootprintEmitter` checks the block under each paw; snow → a 0.07 × 0.09
  pressed print (full depth) turned to the heading, ice or iceberg → nothing, else the dark print particle
  (§5). `PlayerController.Landed` → a 0.24 × 0.42 body dent at 55% depth on snow.
- Ice: §4.5. `PlayerController.HorizontalSpeed` is the requested speed, so a fox sliding with no
  input plays Idle instead of running in place.

## 5. Items

- Per level (§4.3), placed at scene load by `ItemSpawner.Spawn(layout)`:
  - `Fixed`: one item per `ItemPlacement`, at ground (+0.4) or jump height (+1.0) as set;
    a placement on a cell that cannot hold one is skipped with a warning.
  - `Random`: `RandomItemCount` items on cells that can hold one (firm, still blocks: not a hole,
    crumbling, iceberg, or the start),
    picked without replacement and clamped to the number of candidates; each floats at ground
    or jump height, 50/50, so some items require jumping.
- `GameManager.Start` asks `ItemSpawner.Spawn(layout)` for the items (tiles already exist:
  `LevelLoader` builds them in `Awake`), then subscribes to each item's `Collected`.
- Item visual: gold voxel gem (0.34 cube standing on a vertex, smoothness 0.7) under a
  `Visual` child that spins 90°/s and bobs ±0.08 over 1.5 s with a random phase.
- Pickup: sphere trigger (radius 0.3) on the root; on `OnTriggerEnter` from the player →
  spawn `PickupBurst` at the gem, raise `Collected` once, destroy.
- Effects (`EffectAssetBuilder`): one-shot particle bursts of small cubes (mesh particles,
  random 3D rotation, shrinking over life, world space, destroy on stop). One white
  `Particles/Simple Lit` material; each effect's start color tints it.
  `PickupBurst`: 18 gold cubes from a small sphere, fast. `CrumbleDust`: 18 sand cubes from
  a flat box the size of the tile top, slow, heavier gravity. `StepSplash`: 6 small pale cubes
  up from a narrow cone, for steps in shallow water.
- Footprints (on snow, ice, and icebergs see §4.9): `Footprints` is an always-running system with emission off (child of the
  Player, world space, max 64). `FootprintEmitter` on the `Model` receives the clips'
  `Footstep(legs)` animation events, raycasts down from the bottom of each named leg mesh
  (triggers and the player's own controller ignored), and emits one flat dark voxel
  (0.07 × 0.012 × 0.08) on the surface, turned to the player's heading. Prints hold for 60%
  of their 1.5 s life, then shrink away (opaque material; no fading). No prints while
  airborne. Events (set by `CharacterAssetBuilder`): Walk 0% `LegFR,LegBL`, 50%
  `LegFL,LegBR`; Run 25% `LegFL,LegFR`, 75% `LegBL,LegBR`.

## 6. Player

- Player prefab: root pivot at the feet, tag `Player`. `CharacterController` height 0.6,
  radius 0.2, skin width 0.02, step offset 0.1 (level changes need a jump).
  Hierarchy: `Player (PlayerController, CharacterController, PlayerAnimator) → Model, Footprints`
  where `Model` is a nested instance of `Fox.fbx` with an `Animator` (`Fox.controller`, no root
  motion, always animate) and `FootprintEmitter` (§5). The clips key the model root's own transform, so `Model` must
  stay a child at the local origin; never position the fox by moving `Model`.
- `PlayerController` (requires `CharacterController`):
  - Reads `Player/Move` (Vector2), `Player/Jump` and `Player/ToggleWalk` (buttons) from
    `InputSystem.actions`, caching the `InputAction`s on enable. `Player/Restart`,
    `Player/Pause`, and `Player/Jump` (to start from the title) are read by `GameManager`.
  - Bindings: Move = WASD + arrow keys, Jump = Space, ToggleWalk = Left Ctrl, Restart = R,
    Pause = Esc.
    No UI map in the asset, so UI input falls back to the Input System's default UI actions.
  - `IsRunning` starts true; each ToggleWalk press flips it (only while input is enabled).
    Speed is `_runSpeed` (3) when running, `_walkSpeed` (1) otherwise, and `RunningChanged`
    fires on each flip (the HUD shows the mode). A restart reloads the scene, so it starts
    running again.
  - Converts input to camera-relative direction on the XZ plane (W = screen-up).
  - Rotates the model to face movement direction (smooth turn).
  - Coyote time 0.1 s and jump buffer 0.1 s.
  - Disables input when the game state is not `Playing`.
  - Raises `Jumped` when a jump actually starts (after coyote/buffer checks).
- `PlayerAnimator` (`[DefaultExecutionOrder(10)]`, after `PlayerController`): sets `Speed`
  (horizontal speed), `Running`, `Grounded`, `VerticalSpeed`, `WalkPlaybackSpeed`,
  `RunPlaybackSpeed` every frame and the `Jump` trigger on `Jumped`. Parameter names and
  hashes live in `PlayerAnimator.Parameters`.
  `WalkPlaybackSpeed = Speed / _walkReferenceSpeed` (1) and `RunPlaybackSpeed = Speed /
  _runReferenceSpeed` (3), so both clips play at 1× at their own speed; tune in the inspector.
- `Fox.controller` (built by `CharacterAssetBuilder`, all transitions 0.1 s, no exit time):
  - Locomotion states and their entry conditions: Idle = `Speed` < 0.1;
    Walk = `Speed` > 0.1 and not `Running`; Run = `Speed` > 0.1 and `Running`.
    Every pair of locomotion states is connected with the target's conditions.
    Walk/Run speed multipliers are `WalkPlaybackSpeed` / `RunPlaybackSpeed`.
  - Any State → Jump: `Jump` trigger (no transition to self).
  - Jump → Fall: `VerticalSpeed` < 0. Idle/Walk/Run → Fall: not `Grounded` and
    `VerticalSpeed` < −1 (walking off an edge).
  - Fall → Idle / Walk / Run: `Grounded` and the target's locomotion conditions.
  - Rebuilt only when its parameters or state names differ from the above (rebuilding
    regenerates every sub-asset ID); delete the asset to force a rebuild.

## 8. Game flow

```
launch ──▶ Title (Continue target loaded) ──(Space / Continue)──▶ Playing ◀──(Esc / Resume)──▶ Paused
Title ──(Stages)──▶ stage list ──(unlocked stage)──▶ reload ──▶ Playing (that stage)
                                                     │
                     ┌──(all items collected)────────┼──▶ Cleared (clear recorded)
                     │                               └──(player.y < water level)──▶ GameOver
Cleared ──(Space / Next Stage)──▶ reload ──▶ Playing (next stage, crossing worlds)
Cleared with no playable next stage ──(Space / Stages)──▶ reload ──▶ Title, stage list open
R, Restart, Retry ──▶ reload ──▶ Playing (same stage)
Quit to Title (pause menu) ──▶ reload ──▶ Title (Continue target)
```

- `LevelSession` (static, reset by `RuntimeInitializeOnLoadMethod` because domain reload is off)
  carries `OpenAtTitle`, `Stage` (`StageRef`), and `OpenStageSelect` across reloads, and in the
  editor `TestLayout` (§4.8).
- `LevelLoader` (`Level` object, `[DefaultExecutionOrder(-50)]`) in `Awake`: loads
  `PlayerProgress`, then takes the test layout, or at the title the Continue target (so Continue
  just starts what is on screen), or else `LevelSession.Stage` (falling back to the Continue
  target if it no longer exists); builds the map, moves the player to the start tile (controller
  off while moving, yaw 45°), sets the camera's `FramedBounds`, and centers the lake. Exposes
  `Layout`, `Worlds`, `Progress`, `Stage`, `StageTitle` (`Beach 1-3`), `IsFinalStage`,
  `IsLastStageOfWorld`, `IsTestPlay`, and `TryGetNextStage` (the next stage, only if its world
  is unlocked).

- `GameManager` (single instance in the scene, `GameManager` object) owns the state,
  item counts (`CollectedCount`, `TotalCount`), and `ElapsedTime` (0 at the title, counting from
  the start of play, frozen when the state leaves `Playing`/`Paused`). Events: `StateChanged`,
  and `ItemCountChanged` (after spawning and after every pickup). The last pickup switches to
  `Cleared`.
  - `[DefaultExecutionOrder(5)]`, after `PlayerController`: the Space press that leaves the
    title is not also read as a jump.
  - `Awake` picks the first state from `LevelSession.OpenAtTitle` (test play always skips the
    title). `Restart()` reloads the same stage straight into play; `NextStage()` moves to the
    next stage and reloads into play; `StartStage(stage)` plays an unlocked stage from the list
    (the one already loaded at the title just starts); `QuitToTitle()` opens the title;
    `OpenStages()` opens the title on the stage list; `ContinueAfterClear()` (Space on the clear
    card) picks the next stage, a retry in test play, or the stage list. `QuitApplication()`
    quits (stops play mode in the editor).
  - On `Cleared` outside test play: `PlayerProgress.RecordClear(layout, ElapsedTime)` and `Save`;
    `IsNewBest` tells the clear card.
    Items spawn behind the title too.
  - Holds a reference to the scene's `PlayerController` (no singleton); sets
    `PlayerController.InputEnabled` from the state (only in `Playing`). Gravity keeps applying
    while disabled.
  - Pause: `Time.timeScale = 0` while `Paused`, back to 1 on any other state and before a reload.
  - Reads `Player/Restart` (ignored at the title) and `Player/Pause` (toggles
    `Playing`/`Paused`).
  - Water check: the player's feet below `WaterLevel` (`MapMetrics.WaterLevel`, raised by the
    tide, §4.10) → spawn `Splash` at the surface and switch to `GameOver`. The fox keeps sinking
    under gravity. Sets `Tide.IsRunning` on every state change (off only at the title).

### 8.1 UI

UI Toolkit: `Assets/UI/GameUI.uxml` + `GameUI.uss` (hand-written), `GameTheme.tss` (imports the
default runtime theme), `GamePanelSettings.asset` (built by `UIAssetBuilder`; scale with screen
size, 1920×1080 reference). `GameUI` (on the `UI` object with a `UIDocument`; references
`GameManager` and `PlayerController`) shows one overlay per state via the `hidden` class.
No `EventSystem` is needed; UI input comes from the Input System's default UI actions.

- **Style: minimal flat**, picked from Codex-generated mockups (voxel, soft casual, minimal).
  Inter Regular (OFL, copied from the Unity editor with its license) for all text; white text;
  dark translucent navy panels (`rgba(14, 24, 40, 0.62–0.78)`) with a 1 px white 10–14% border;
  gold only on gems. No blur (UI Toolkit has none).
- **Icons**: `GameIcon` (`[UxmlElement]`, `kind` attribute) draws flat vector icons with
  `Painter2D` in the element's USS `color`: `Gem` (three gold faces), `Clock`, `Play`,
  `Restart`, `Quit`, `Walk` (›), `Run` (»), `FoxMark` (the app icon's fox head, eyes cut out),
  `Check`, `Lock`, `Stages` (2 × 2 squares), `Wave` (two wave strokes).
- **HUD** (hidden at the title): top-left pill with gem + `n / total` (bumps to 112% for 0.12 s
  on a pickup), top-center pill with the stage title, `BEACH 1-3` (`TEST PLAY` in test play),
  and beside it, on tide stages only, a tide pill: wave icon, a 140 px bar filled to the current
  tide (0 = low, full = high), and a chevron pointing up while the water rises, down while it
  falls; top-right pill with `m:ss`. Bottom-left hint row (fades out outside `Playing`):
  `» fox RUNNING` / `› fox WALKING`, `[Ctrl] Walk / Run`, `[R] Restart`, `[Esc] Pause`, with key
  caps and thin separators.
- **Title**: light dim over the live scene; fox mark, `FOX ISLAND` (120 px, letter-spaced),
  `▶ Continue 1-3` (`Start 1-1` before the first clear), `Stages`, `[Space] to continue`, and a
  quiet `Quit` button.
- **Stage list** (title only): card "Stages", one row per world: accent bar in the world's color,
  name, a lock icon while locked, then stage cards `w-s` with a green check and the best time
  (`m:ss.s`) once cleared, `—` otherwise. The Continue target has a gold outline; locked worlds'
  cards are dimmed and disabled. Clicking an unlocked card plays it. `Back (Esc)` closes the list.
- **Pause**: card "Paused" with Resume, Restart, Quit to Title.
- **Game Over**: card "Game Over" with `Restart (R)`.
- **Clear**: card "Clear!" ("World Clear!" on a world's last stage, "All Clear!" on the last
  stage), divider, clock + `m:ss.s` and gem + `n / total`, `New best!` or `Best m:ss.s`, then
  `▶ Next Stage (Space)` (if a next stage is playable), `Retry (R)`, and `Stages` (`Stages
  (Space)` when there is no next stage). In test play only `Retry (R)`, no best time.
- Buttons act only in the state that shows them (a hidden button can keep focus and Space
  would submit it), and focus is cleared on every state change.
- Motion: overlays fade (opacity 0.3 s; `.overlay.hidden` hides by opacity + visibility so the
  transition can run), cards scale in from 94%, buttons brighten on hover and press to 98%.

### 8.2 Worlds and progress

- `PlayerProgress` (plain C#) keeps the best clear time per stage, keyed by the layout's asset
  name, in `Application.persistentDataPath/progress.json` (`JsonUtility`; a missing or broken file
  means a fresh start). Test play never records. Renaming a stage drops its record.
- A stage is cleared once it has a best time. World 1 is always unlocked; world n unlocks when
  every stage of world n−1 is cleared and world n−1 is itself unlocked (an empty world counts as
  cleared). Locking is per world: every stage of an unlocked world can be played in any order.
- Continue target: the first uncleared stage of an unlocked world, in play order; after
  everything is cleared, the last stage.
- Editor: `Tools/MyGame/Reset Progress` deletes the file (with a confirmation), `Show Progress
  File` reveals it.
