# Voxel Animal Platformer — Development Plan

A small Unity 3D game: a voxel animal walks and jumps around a 4×4 tile map viewed from a
quarter (isometric) camera, collecting randomly placed items. Falling off ends the game;
collecting every item clears it. Either way, the player can restart.

This file is the source of truth for implementation.

---

## 1. Decisions

| Topic            | Decision                                                                                  |
| ---------------- | ----------------------------------------------------------------------------------------- |
| Engine           | Unity 6000.6.3f1, URP blank template                                                      |
| Character        | Voxel animal generated by a **Blender Python script** (default: fox — swappable)          |
| Character rig    | Armature with rigid parts: each body part mesh is 100% weighted to one bone               |
| Animations       | `Idle`, `Walk`, `Jump`, `Fall` — keyframed by the same Blender script, exported in FBX    |
| Map              | 4×4 grid, tile = 1×1 unit, with holes, height levels, and crumbling tiles                 |
| Items            | Randomly placed at game start (every load / restart)                                      |
| Camera           | Fixed orthographic quarter view, whole map always visible                                 |
| Controls         | WASD = move (camera-relative), Space = jump, R = restart                                  |
| Movement         | Free (continuous) movement with `CharacterController`, not tile-by-tile stepping           |
| Input            | Input System project-wide actions: `Input/PlayerControls.inputactions`, `Player` map only  |
| Lose condition   | Player falls below the kill plane (`y < -5`)                                              |
| Win condition    | All items collected                                                                       |
| Restart          | Reload the scene; items are re-randomized on load                                         |

## 3. Character pipeline (Blender Python)

### 3.1 Script contract

Run headless:

```
blender --background --python Tools/Blender/generate_character.py -- --animal fox --out Art/Character/Fox.fbx
```

The script must:

1. Start from an empty scene (delete default cube/camera/light).
2. Load voxel data for the chosen animal from `animals/<name>.py`.
3. Build one mesh object **per body part** from its voxels.
   - Merge voxels of a part into a single mesh; remove interior faces (only emit a face when the
     neighbouring voxel is empty) to keep poly count low.
   - Color via a small palette: one material per palette entry, or vertex colors. Prefer
     materials — Unity imports them without extra shader work.
4. Create an armature: `Root → Body → {Head, LegFL, LegFR, LegBL, LegBR, Tail}`.
   - Each bone's head sits at the part's pivot (hip/shoulder joint, neck, tail base).
   - Parent each part mesh to its bone with a single vertex group at weight 1.0.
5. Keyframe four actions on the armature (rotations only, plus Body bob):
   - `Idle` (loop, ~1.0 s): subtle body bob, slow tail sway.
   - `Walk` (loop, ~0.5 s): diagonal leg pairs swing ±30°, body bob, tail sway.
   - `Jump` (one-shot, ~0.3 s): legs tuck, body tilts up.
   - `Fall` (loop, ~0.4 s): legs spread, tail up.
6. Export FBX: `bake_anim_use_all_actions=True`, `add_leaf_bones=False`,
   `apply_scale_options='FBX_SCALE_ALL'`, `axis_forward='-Z'`, `axis_up='Y'`.

### 3.2 Voxel data format

```python
VOXEL_SIZE = 0.0625  # 1/16 unit per voxel; character ~0.6 units tall

PALETTE = {
    "o": (0.93, 0.47, 0.13),  # orange fur
    "w": (0.97, 0.95, 0.90),  # white fur
    "k": (0.10, 0.08, 0.08),  # eyes / nose / paws
}

# Each part: pivot (in voxels) + list of Y-layers (bottom to top),
# each layer a list of strings along Z (rows) and X (columns). "." = empty.
PARTS = {
    "Body": {"pivot": (0, 5, 0), "layers": [...]},
    "Head": {"pivot": (0, 8, 3), "layers": [...]},
    ...
}
```

Adding a new animal = adding one file under `animals/`. Nothing else changes.

### 3.3 Acceptance

- Script runs headless with exit code 0 on Blender 4.x.
- FBX imports into Unity as a Generic rig with four clips named `Idle`, `Walk`, `Jump`, `Fall`.
- Character faces +Z in Unity, feet at y = 0, height ≈ 0.6 units.

## 4. Map

### 4.1 Tile types

| Type        | Symbol | Behaviour                                                                                 |
| ----------- | ------ | ----------------------------------------------------------------------------------------- |
| Hole        | `.`    | No tile. Player falls through.                                                            |
| Solid       | `0`–`2`| Static tile at height level N (level height = 0.5 units).                                 |
| Crumbling   | `C`    | Level 0. After the player stands on it for 0.8 s it shakes, then drops away; it respawns 3 s later. |
| Start       | `S`    | Solid level 0; player spawns here. Never holds an item.                                   |

Crumbling tiles respawn so that no item can become permanently unreachable.

### 4.2 Initial layout

Row 0 is the row nearest the camera. Tuned during playtesting.

```
row 3:  1  .  2  2
row 2:  C  1  .  C
row 1:  0  .  C  1
row 0:  S  0  0  .
```

### 4.3 Data

`MapLayout` ScriptableObject stores the layout as text rows, exactly in the §4.2 notation
(first row = farthest from the camera, tokens separated by spaces). It parses them into
`TileSpec` (type + level) on demand and warns in `OnValidate` on bad tokens, ragged rows,
or a start-tile count other than one.
`MapBuilder` (on the `Map` object) instantiates tile prefabs from it in `Awake`.

### 4.4 Coordinates

- Tile `(column, row)` is centered at world `(column, *, row)`; the map spans
  x, z ∈ [-0.5, 3.5]. Row 0 / column 0 is the corner nearest the camera.
- A tile's top surface is at `y = level × 0.5`; every tile is a block down to `y = -0.5`
  (`MapMetrics`). The top 0.15 is a colored slab (grass / crumbling / start), the rest dirt.
- The collider covers the full 1×1 cell; visuals are inset by 0.04 so the grid reads clearly.
- The camera frames the box center `(1.5, 0.85, 1.5)`, size `(4, 2.7, 4)`: tile tops from
  level 0 down to -0.5, up to level 2 plus jump apex (≈ 2.2).

### 4.5 Physics tuning targets

- Walk speed: 3 units/s.
- Jump apex: ~1.2 units above takeoff → can climb one level (0.5) comfortably, two levels (1.0) barely.
- Horizontal jump reach at full speed: ≥ 1.6 units → a one-tile hole is crossable.
- Gravity: ~-25 units/s² for snappy feel.

## 5. Items

- Count: `GameConfig.itemCount` (default 4).
- Placement at scene load by `ItemSpawner`:
  - Candidate tiles: Solid tiles only (not Start, not Crumbling, not Hole).
  - Pick without replacement; `itemCount` is clamped to the number of candidates.
  - Each item floats either at ground height (+0.4) or at jump height (+1.0), chosen randomly
    (50/50), so some items require jumping.
- Item visual: small voxel gem/coin, rotating and bobbing.
- Pickup: trigger collider; on enter → notify `GameManager`, play effect, destroy.

## 6. Player

- Player prefab: root pivot at the feet, tag `Player`. `CharacterController` height 0.6,
  radius 0.2, skin width 0.02, step offset 0.1 (level changes need a jump).
  Stand-in visual: orange capsule plus a dark "nose" cube showing the facing direction.
- `PlayerController` (requires `CharacterController`):
  - Reads `Player/Move` (Vector2) and `Player/Jump` (button) from `InputSystem.actions`,
    caching the `InputAction`s on enable. `Player/Restart` is read by `GameManager`.
  - Bindings: Move = WASD + arrow keys, Jump = Space, Restart = R. No UI map in the asset,
    so UI input falls back to the Input System's default UI actions.
  - Converts input to camera-relative direction on the XZ plane (W = screen-up).
  - Rotates the model to face movement direction (smooth turn).
  - Coyote time 0.1 s and jump buffer 0.1 s.
  - Disables input when the game state is not `Playing`.
- `PlayerAnimator`: drives Animator parameters `Speed` (float), `Grounded` (bool),
  `VerticalSpeed` (float), trigger `Jump`.
  - States: Idle ↔ Walk by `Speed`; any → Jump on trigger; Jump → Fall when `VerticalSpeed < 0`;
    Fall → Idle/Walk when `Grounded`.

## 7. Camera

- `QuarterViewCamera` (`[ExecuteAlways]`): orthographic, rotation `(30°, 45°, 0°)`, placed
  20 units back from the center of `FramedBounds` (§4.4).
- Orthographic size is computed from the projected corners of `FramedBounds` so the box
  fills 70% of the tighter screen dimension; recomputed when the aspect ratio changes.
- `MapBuilder` may later set `FramedBounds` from the actual map.
- No follow logic needed at this map size.
- Scene setup (camera, directional light, trilight ambient) is reproducible via
  `Tools/MyGame/Setup Main Scene` (`MainSceneSetup`).

## 8. Game flow

```
Playing ──(all items collected)──▶ Cleared
   │
   └──(player.y < -5)──────────▶ GameOver

Cleared / GameOver ──(R key or Restart button)──▶ reload scene ──▶ Playing
```

- `GameManager` (single instance in the scene, `GameManager` object) owns the state,
  remaining item count, and exposes events: `StateChanged`, `ItemCollected`.
  - Holds a reference to the scene's `PlayerController` (no singleton); sets
    `PlayerController.InputEnabled` from the state. Gravity keeps applying while disabled.
  - Reads `Player/Restart`; `Restart()` reloads the active scene by build index.
  - Kill plane `_killPlaneY = -5`.
- UI is UI Toolkit: `Assets/UI/GameUI.uxml` + `GameUI.uss` (hand-written text),
  `GameTheme.tss` (imports the default runtime theme), `GamePanelSettings.asset`
  (built by `UIAssetBuilder`; scale with screen size, 1920×1080 reference).
  `GameUI` (on the `UI` object with a `UIDocument`) toggles panels via the `hidden` class.
  No `EventSystem` is needed; UI input comes from the Input System's default UI actions.
- HUD: items collected `n / total`.
- GameOver panel: "Game Over" + Restart button.
- Cleared panel: "Clear!" + elapsed time + Restart button.
- R restarts at any time, including mid-play.
