# Voxel Animal Platformer — Development Plan

A small Unity 3D game: a voxel animal walks and jumps around small tile maps (levels) viewed from a
quarter (isometric) camera, collecting randomly placed items. Falling off ends the game;
collecting every item clears it. Either way, the player can restart.

This file is the source of truth for implementation.

| Topic            | Decision                                                                                  |

| Input            | Input System project-wide actions: `Input/PlayerControls.inputactions`, `Player` map only  |
| Lose condition   | Player touches the water (`y < MapMetrics.WaterLevel` = −0.3)                             |
| Win condition    | All items collected                                                                       |
| Restart          | Reload the scene; items are re-randomized on load. The first launch opens at the title     |
| UI               | UI Toolkit, minimal flat style (chosen from Codex-generated mockups), Inter font          |

## 3. Character pipeline (Blender Python)

### 3.1 Script contract

Blender 5.2 LTS, headless (`blender.exe` in `C:\Program Files\Blender Foundation\Blender 5.2\`):

```
blender --background --factory-startup --python Tools/Blender/generate_character.py -- \
    --animal fox --out Unity/Assets/Art/Character/Fox.fbx [--preview DIR] [--blend PATH]
```

The script:

1. Resets to an empty factory scene at 30 fps.
2. Loads `animals/<name>.py` (see §3.2).
3. Builds one mesh object `Mesh_<Part>` **per body part**. A face is emitted only when the
   neighbouring voxel of the *same part* is empty; faces against other parts stay, because
   they show when parts rotate. One material per palette entry used by the part.
4. Builds the armature `Fox`: `Root → Body → {Head, LegFL, LegFR, LegBL, LegBR, Tail}`.
   Each bone's head sits at the part's pivot and points up (+Z, roll 0), so bone X pitches
   (+ swings a leg back, dips the head, raises the tail), bone Y yaws, bone Z rolls.
   Each part mesh is parented to its bone (`parent_type = 'BONE'`) keeping its world placement:
   rigid parts, no skinning, plain `MeshRenderer`s in Unity.
5. Keys five actions, every bone on every key (so clips never inherit each other's pose):
   `Idle` (30 f loop: body bob, head nod, tail sway), `Walk` (16 f loop: diagonal leg pairs
   ±25°; at each stride extreme the body rolls ±4° and twists ±3° with the weight shift while
   the head counters by ∓2° and the tail swings against the twist; body bob ×2 at the passing
   poses), `Run` (12 f loop, bound gait: front legs together, back legs together;
   stretch in the air → front feet land, nose dips → legs gather under the body → back feet
   push off, nose rises; the head takes back half the body pitch, the tail trails),
   `Jump` (9 f one-shot: front legs forward, back legs back,
   nose up, tail up), `Fall` (12 f loop: legs spread, nose down, tail up, slight flutter).
6. Exports FBX with `bake_anim_use_all_actions=True`, `add_leaf_bones=False`,
   `apply_scale_options='FBX_SCALE_ALL'`, `axis_forward='-Z'`, `axis_up='Y'`,
   `armature_nodetype='NULL'`. Take names come out as `Fox|<Action>`; M7 renames the
   Unity clips to `Idle`, `Walk`, `Run`, `Jump`, `Fall`.
7. `--preview DIR` renders one Workbench still per clip (flat palette colors, cavity, outline;
   `Raw` view transform because Unity reads the palette as sRGB). `--blend PATH` saves the scene.

### 3.2 Voxel data format

```python
VOXEL_SIZE = 0.05   # fox: 6 wide, 19 long, 12 tall voxels -> 0.3 x 0.95 x 0.6 units

PALETTE = {"o": (0.93, 0.47, 0.13), "w": (0.97, 0.95, 0.90), "k": (0.10, 0.08, 0.08)}

PARTS = {
    "Head": {
        "parent": "Body",
        "pivot": (0, -3, 6),                        # voxel-boundary coordinates
        "boxes": [
            ("o", (-3, -8, 5), (2, -4, 9)),         # inclusive voxel index ranges
            ("k", (-2, -8, 7), (-2, -8, 7)),        # later boxes paint over earlier ones
            ...
        ],
    },
    ...
}
```

Axes are Blender's: +X is the animal's left, the nose points to −Y, +Z is up, z = 0 is the
ground. Adding a new animal = adding one file under `animals/` with the same part names.

### 3.3 Acceptance

- Script runs headless with exit code 0 on Blender 5.2.
- Re-importing the FBX in Blender shows 7 part meshes parented to their bones, 8 bones,
  5 actions with the right lengths, 3 materials.
- FBX imports into Unity without warnings as a Generic rig facing +Z, feet at y ≈ 0.

### 3.4 Unity import (`CharacterAssetBuilder`, `CharacterMaterialPostprocessor`)

- Generic rig, avatar from this model, no cameras/lights/blend shapes/visibility.
- **Bake Axis Conversion stays off.** With it on, the rest pose is fixed but the clips' root
  curves are not, and the animated fox tips over 90°. Off, the model root keeps Blender's
  −90° X rotation and everything agrees; Blender −Y maps to Unity +Z.
- Clips renamed from `Fox|Idle` to `Idle` etc.; Idle, Walk, Run, Fall loop, Jump does not.
- `CharacterMaterialPostprocessor` imports every material under `Assets/Art/Character/` as URP
  Lit with the FBX diffuse color unchanged (read as sRGB, like the tile palette), smoothness
  0.1, metallic 0. URP's default FBX conversion washed the palette out.

## 4. Map

### 4.1 Tile types

| Type        | Symbol | Behaviour                                                                                 |
| ----------- | ------ | ----------------------------------------------------------------------------------------- |
| Hole        | `.`    | No tile, just water. Falling in ends the game.                                            |
| Solid       | `0`–`2`| Static tile at height level N (level height = 0.5 units).                                 |
| Crumbling   | `C`    | Level 0. The first landing starts it: it shakes for 0.8 s (the warning, ramping from 30% to full strength), then sinks into the lake in a burst of `CrumbleDust`, splashing (`TileSplash`) as its top goes under; it respawns 3 s after dropping, waiting while anything occupies its cell. |
| Start       | `S`    | Solid level 0; player spawns here. Never holds an item.                                   |

Crumbling tiles respawn so that no item can become permanently unreachable.

### 4.2 Level 1 layout

Row 0 is the row nearest the camera. Tuned during playtesting.

```
row 3:  1  .  2  2
row 2:  C  1  .  C
row 1:  0  .  C  1
row 0:  S  0  0  .
```

### 4.3 Data

- `MapLayout` (one asset per level under `Assets/ScriptableObjects/Levels/`) stores the tiles
  as text rows in the §4.2 notation (first row = farthest from the camera, tokens separated
  by spaces), 2–8 per side (`MinSize`, `MaxSize`). Parsing checks only the shape (tokens,
  rectangular rows), so a layout mid-edit still loads; content rules live in
  `MapLayoutValidator` (§4.8), whose errors `OnValidate` logs. `SetTiles` writes rows back
  (`TileSpec.ToToken`).
- Items per layout: `ItemMode` `Random` (`RandomItemCount`, default 4) or `Fixed` (`Items`:
  `ItemPlacement` = cell + `InAir`).
- `LevelList` (`Assets/ScriptableObjects/LevelList.asset`): the layouts in play order.
- `LevelLoader` (§8) picks the layout at scene load and calls `MapBuilder.Build(layout)`;
  `MapBuilder` keeps a cell → tile lookup (`TryGetTile`).

### 4.4 Coordinates

- Tiles are `TileSize = 1.5` units wide and deep (height per level stays 0.5).
  Tile `(column, row)` is centered at world `(column × 1.5, *, row × 1.5)`; a 4×4 map spans
  x, z ∈ [-0.75, 5.25]. Row 0 / column 0 is the corner nearest the camera.
- A tile's top surface is at `y = level × 0.5`. Its collider is a block down to `y = -0.5`
  (`TileBottom`); its visual is a pillar down to the lake bed at `y = -1.5` (`LakeBedY`), so
  tiles stand in the water (§4.7). The top 0.15 is a colored slab (grass / crumbling / start),
  the rest dirt.
- Prefab hierarchy: `Root (Tile, BoxCollider[, CrumblingTile]) → Visual → Top, Body`.
  `CrumblingTile` moves only `Visual`; the collider stays put and is disabled while the tile
  is gone. The player notifies it from `OnControllerColliderHit` on an upward-facing hit.
- The collider covers the full cell; visuals are inset by 0.04 so the grid reads clearly.
- The camera frames `MapMetrics.FramedBounds(width, depth, jumpHeight)`: `GridBounds` (tile
  bottoms to the top of level 2) raised by the player's jump height. `LevelLoader` sets it per
  level at runtime; `MainSceneSetup` sets it for level 1 so the scene reads right in edit
  mode. For a 4×4 map: center `(2.25, 0.85, 2.25)`, size `(6, 2.7, 6)`.

### 4.5 Physics tuning targets

- Run speed 3 units/s by default; walk speed 1 unit/s in walk mode (Left Ctrl toggles).
- Jump apex: ~1.2 units above takeoff → can climb one level (0.5) comfortably, two levels (1.0) barely.
- Horizontal jump reach (air time ≈ 0.62 s): walking ≈ 0.62, running ≈ 1.86 units. A one-tile
  hole is 1.5 units edge to edge (the center has to travel ≈ 1.1–1.5 with the 0.2 radius), so
  crossing a hole takes a running jump.
- Gravity: ~-25 units/s² for snappy feel.

### 4.6 Grass

- `GrassField` (on the `Map` object, builds in `Start` after `MapBuilder.Awake`) scatters voxel
  grass on **Solid** tiles only (not Start, Crumbling, Hole). Decoration only: no colliders.
- Each solid tile gets one coverage: **Bare** (no grass), **Sparse** (3–5 tufts at least 0.3
  apart, kept 0.2 from the edge), or **Full** (a 4×4 grid over the tile with ±30% jitter and a
  10% chance to skip a cell). Tiles are split by share, not rolled one by one, so every build
  mixes all three: 25% bare, 35% full, the rest sparse, assigned by a seeded shuffle.
  Positions are seeded per tile coordinate, so the field is identical every run (current
  layout: 2 bare, 3 sparse, 3 full, 58 tufts). Tufts are children of their tile, at the tile
  top, with a random yaw.
- A tuft is one of 4 code-built meshes: 7–11 axis-aligned blades, 0.045 wide, 0.12–0.2 tall
  (up to the fox's body, whose underside is at 0.15). Every vertex carries its blade's random
  phase in `uv0.x` and its blade base (x, z, object space) in `uv1`; mesh bounds are padded by
  0.2 for the bend. Material `Grass_Blade` uses `Assets/Art/Shaders/Grass.shader`
  (`MyGame/Grass`; brighter than the tile grass so it reads at camera distance); no shadow
  casting. Tufts themselves never move: **each blade bends in the vertex shader**, rotating
  rigidly about its own base (normals rotated too).
- Wind (`_GrassWind`): each blade leans downwind by 0–7°, driven by two sines whose phase
  follows the blade base along the wind direction (gusts travel across the map) plus its
  random phase (neighbouring blades differ). Wind (1, 0, 0.4), 1.1 Hz, wavelength 3 units.
- Trampling (`_GrassTrample[16]`, `_trampler` = the Player): `GrassField` records the player's
  position every `recoverTime / 16` s into a ring and sends each sample with strength
  `1 − age / 0.6 s`, plus the current position at strength 1. Per blade the shader takes the
  strongest `saturate(1 − distance / 0.4) × strength` among samples within 0.3 vertically,
  and leans away from that sample by up to 65° (smoothstepped) while the wind lean fades.
  So grass flattens under the fox and stands back up over 0.6 s behind it, with no per-blade
  state on the CPU. `TrailLength` in `GrassField` must match `GRASS_TRAIL_LENGTH` in the shader.
- The shader has ForwardLit (main light, soft shadows, SH ambient), DepthOnly, and
  DepthNormals passes that share the same bend, so SSAO follows the bent blades.
- `MainSceneSetup` resets `GrassField` to its code defaults on every build, so tune it by
  changing the defaults in `GrassField.cs` (inspector changes are for trying values out).

### 4.7 Water

- The grid stands in a lake: the holes and everything around the grid are water at
  `MapMetrics.WaterLevel = -0.3` (level-0 tiles rise 0.3 above it). Touching it is game over (§8).
- `Lake` (scene object, built by `MainSceneSetup`; `LevelLoader` centers it on each level's grid): `WaterSurface`
  builds a flat 40 × 40 grid mesh (0.5 cells) in `Awake`, play mode only, like the grass;
  `Bed` is a sand cube whose top is at `LakeBedY = -1.5`. The camera background is the deep
  water color in case the edge ever shows.
- Material `Water` uses `Assets/Art/Shaders/Water.shader` (`MyGame/Water`, transparent, no
  depth write, receives shadows). `MapAssetBuilder` sets its properties explicitly:
  - Waves: three travelling sines (wavelengths 2.5, ×0.63, ×0.41; height 0.02 and smaller;
    0.4 units/s) move the vertices; the fragment recomputes the slope, adds two small ripples,
    and exaggerates it ×3 for the normal.
  - Depth: the camera depth texture (forced on for the main camera) gives the water depth
    behind each pixel, measured vertically. Color and opacity blend from shallow
    (0.36, 0.78, 0.80, α 0.45) to deep (0.12, 0.38, 0.62, α 0.92) over 0.8 units, so the
    pillars show just under the surface and fade out below.
  - Foam: a crisp band where the depth is under 0.06 (wobbling ±50%), plus a thinner band
    drifting from the shore out to 4× that width every ~3 s.
- Splashes: `Splash` (22 pale cubes up from a cone) where the fox touches the water;
  `TileSplash` (36 cubes up from a tile-sized flat box) when a crumbling tile's top goes under.

### 4.8 Map tool

`Tools/MyGame/Map Tool` (`Editor/MapTool/MapToolWindow`, IMGUI) edits `LevelList` and the
layouts. Every edit is undoable (`Undo.RecordObject`) and saved to the asset at the end of a
stroke.

- **Level list** (left): reorderable play order; New (blank 4×4 at level 0, start at (0, 0),
  `Levels/LevelNN.asset`), Duplicate (copy inserted after the selection), Remove (from the list,
  or also move the asset to the trash after a confirmation; the list keeps at least one level).
  Name field renames the asset.
- **Grid** (top-down): row 0 at the bottom (camera side), column 0 on the left, axis numbers
  match the check messages. Cell color = tile type / level, label = level, `C`, or `S`;
  `◆` / `◆ ↑` = fixed item on the ground / in the air.
- **Brushes** (keys 1–9, left-drag paints): Hole, Level 0/1/2, Crumbling, Start, Item, Item (air),
  Erase item. Start keeps a single start tile (the old one becomes level 0). Painting a non-solid
  tile removes its item. Item brushes work only on solid tiles and switch the layout to `Fixed`.
- **Size**: width × depth (2–8), grown or cropped from the (0, 0) corner (new cells level 0);
  Shift ◀▶▲▼ moves everything one cell with wrap-around.
- **Items**: mode popup; `Random` count slider (0–32), or `Fixed` with a count and Clear Items.
- **Checks** (`MapLayoutValidator.Validate` → `LayoutReport`: issues + per-cell `Reachability`),
  rerun on every edit; clicking an issue outlines its cell.
  - Errors: rows do not parse, size outside 2–8, start count ≠ 1, fixed item off a solid tile or
    two on one cell, no items. Play This Level is disabled while there are errors.
  - Warnings: more random items than solid tiles, random items able to land on unreachable
    tiles, unreachable tiles (red outline) and fixed items, tiles that need a two-level jump
    (orange outline).
  - Reachability (approximate, §4.5): breadth-first from the start over standable tiles
    (everything but holes), 4-neighbour moves: up one level is easy, up two is "hard" (still
    counted), any drop is fine; a running jump crosses one hole in a straight line onto a tile
    no higher than the takeoff. Air items count as reachable with their tile (jump apex 1.2).
- **3D Preview in Scene View** (`MapToolPreview`): a `[Map Preview]` root in the Main scene with
  its own `MapBuilder`, `GrassField`, and `WaterSurface` copied from the scene's, rebuilt on every
  edit and framed in the Scene view. Every object in it is `HideFlags.DontSave`, so saving the
  scene never writes it. Cleared when the window closes, the toggle goes off, or play mode starts.
- **▶ Play This Level** (`MapToolPlayMode`): saves, opens the Main scene, stores the layout GUID
  in `SessionState` (`LevelSession.TestLayoutKey`), and enters play mode. `LevelSession.TestLayout`
  makes `LevelLoader` load it, the title is skipped, and the HUD shows `TEST PLAY`; the key is
  erased when play mode ends.

## 5. Items

- Per level (§4.3), placed at scene load by `ItemSpawner.Spawn(layout)`:
  - `Fixed`: one item per `ItemPlacement`, at ground (+0.4) or jump height (+1.0) as set;
    a placement off a solid tile is skipped with a warning.
  - `Random`: `RandomItemCount` items on Solid tiles only (not Start, not Crumbling, not Hole),
    picked without replacement and clamped to the number of candidates; each floats at ground
    or jump height, 50/50, so some items require jumping.
- `GameManager.Start` asks `ItemSpawner.Spawn(layout)` for the items (tiles already exist:
  `LevelLoader` builds them in `Awake`), then subscribes to each item's `Collected`.
- Item visual: gold voxel gem (0.34 cube standing on a vertex, smoothness 0.7) under a
  `Visual` child that spins 90°/s and bobs ±0.08 over 1.5 s with a random phase.
- Pickup: sphere trigger (radius 0.3) on the root; on `OnTriggerEnter` from the player →
  spawn `PickupBurst` at the gem, raise `Collected` once, destroy.
- Effects (`EffectAssetBuilder`): one-shot particle bursts of small cubes (mesh particles,
  random 3D rotation, shrinking over life, world space, destroy on stop). One white
  `Particles/Simple Lit` material; each effect's start color tints it.
  `PickupBurst`: 18 gold cubes from a small sphere, fast. `CrumbleDust`: 18 sand cubes from
  a flat box the size of the tile top, slow, heavier gravity.
- Footprints: `Footprints` is an always-running system with emission off (child of the
  Player, world space, max 64). `FootprintEmitter` on the `Model` receives the clips'
  `Footstep(legs)` animation events, raycasts down from the bottom of each named leg mesh
  (triggers and the player's own controller ignored), and emits one flat dark voxel
  (0.07 × 0.012 × 0.08) on the surface, turned to the player's heading. Prints hold for 60%
  of their 1.5 s life, then shrink away (opaque material; no fading). No prints while
  airborne. Events (set by `CharacterAssetBuilder`): Walk 0% `LegFR,LegBL`, 50%
  `LegFL,LegBR`; Run 25% `LegFL,LegFR`, 75% `LegBL,LegBR`.

## 6. Player

- Player prefab: root pivot at the feet, tag `Player`. `CharacterController` height 0.6,
  radius 0.2, skin width 0.02, step offset 0.1 (level changes need a jump).
  Hierarchy: `Player (PlayerController, CharacterController, PlayerAnimator) → Model, Footprints`
  where `Model` is a nested instance of `Fox.fbx` with an `Animator` (`Fox.controller`, no root
  motion, always animate) and `FootprintEmitter` (§5). The clips key the model root's own transform, so `Model` must
  stay a child at the local origin; never position the fox by moving `Model`.
- `PlayerController` (requires `CharacterController`):
  - Reads `Player/Move` (Vector2), `Player/Jump` and `Player/ToggleWalk` (buttons) from
    `InputSystem.actions`, caching the `InputAction`s on enable. `Player/Restart`,
    `Player/Pause`, and `Player/Jump` (to start from the title) are read by `GameManager`.
  - Bindings: Move = WASD + arrow keys, Jump = Space, ToggleWalk = Left Ctrl, Restart = R,
    Pause = Esc.
    No UI map in the asset, so UI input falls back to the Input System's default UI actions.
  - `IsRunning` starts true; each ToggleWalk press flips it (only while input is enabled).
    Speed is `_runSpeed` (3) when running, `_walkSpeed` (1) otherwise, and `RunningChanged`
    fires on each flip (the HUD shows the mode). A restart reloads the scene, so it starts
    running again.
  - Converts input to camera-relative direction on the XZ plane (W = screen-up).
  - Rotates the model to face movement direction (smooth turn).
  - Coyote time 0.1 s and jump buffer 0.1 s.
  - Disables input when the game state is not `Playing`.
  - Raises `Jumped` when a jump actually starts (after coyote/buffer checks).
- `PlayerAnimator` (`[DefaultExecutionOrder(10)]`, after `PlayerController`): sets `Speed`
  (horizontal speed), `Running`, `Grounded`, `VerticalSpeed`, `WalkPlaybackSpeed`,
  `RunPlaybackSpeed` every frame and the `Jump` trigger on `Jumped`. Parameter names and
  hashes live in `PlayerAnimator.Parameters`.
  `WalkPlaybackSpeed = Speed / _walkReferenceSpeed` (1) and `RunPlaybackSpeed = Speed /
  _runReferenceSpeed` (3), so both clips play at 1× at their own speed; tune in the inspector.
- `Fox.controller` (built by `CharacterAssetBuilder`, all transitions 0.1 s, no exit time):
  - Locomotion states and their entry conditions: Idle = `Speed` < 0.1;
    Walk = `Speed` > 0.1 and not `Running`; Run = `Speed` > 0.1 and `Running`.
    Every pair of locomotion states is connected with the target's conditions.
    Walk/Run speed multipliers are `WalkPlaybackSpeed` / `RunPlaybackSpeed`.
  - Any State → Jump: `Jump` trigger (no transition to self).
  - Jump → Fall: `VerticalSpeed` < 0. Idle/Walk/Run → Fall: not `Grounded` and
    `VerticalSpeed` < −1 (walking off an edge).
  - Fall → Idle / Walk / Run: `Grounded` and the target's locomotion conditions.
  - Rebuilt only when its parameters or state names differ from the above (rebuilding
    regenerates every sub-asset ID); delete the asset to force a rebuild.

## 7. Camera

- `QuarterViewCamera` (`[ExecuteAlways]`): orthographic, rotation `(30°, 45°, 0°)`, placed
  20 units back from the center of `FramedBounds` (§4.4).
- Orthographic size is computed from the projected corners of `FramedBounds` so the box
  fills 85% of the tighter screen dimension (set by `MainSceneSetup`); recomputed when the
  aspect ratio changes.
- No follow logic: `LevelLoader` frames each whole level (up to 8×8) at load.
- Scene setup (camera, directional light, trilight ambient) is reproducible via
  `Tools/MyGame/Setup Main Scene` (`MainSceneSetup`).

## 8. Game flow

```
first launch ──▶ Title ──(Space or Press Start)──▶ Playing (level 1) ◀──(Esc / Resume)──▶ Paused
                                                     │
                     ┌──(all items collected)────────┼──▶ Cleared
                     │                               └──(player.y < WaterLevel)──▶ GameOver
Cleared ──(Space / Next Level)──▶ reload ──▶ Playing (next level)
Cleared on the last level ("All Clear!") ──(Space / Back to Title)──▶ Title
R, Restart, Retry ──▶ reload ──▶ Playing (same level)
Quit to Title (pause menu) ──▶ reload ──▶ Title (level 1)
```

- `LevelSession` (static, reset by `RuntimeInitializeOnLoadMethod` because domain reload is off)
  carries `OpenAtTitle` and `LevelIndex` across reloads, and in the editor `TestLayout` (§4.8).
- `LevelLoader` (`Level` object, `[DefaultExecutionOrder(-50)]`) in `Awake`: takes the test
  layout or `LevelList[LevelIndex]` (clamped), builds the map, moves the player to the start tile
  (controller off while moving, yaw 45°), sets the camera's `FramedBounds`, and centers the lake.
  Exposes `Layout`, `LevelNumber`, `LevelCount`, `HasNextLevel`, `IsTestPlay`.

- `GameManager` (single instance in the scene, `GameManager` object) owns the state,
  item counts (`CollectedCount`, `TotalCount`), and `ElapsedTime` (0 at the title, counting from
  the start of play, frozen when the state leaves `Playing`/`Paused`). Events: `StateChanged`,
  and `ItemCountChanged` (after spawning and after every pickup). The last pickup switches to
  `Cleared`.
  - `[DefaultExecutionOrder(5)]`, after `PlayerController`: the Space press that leaves the
    title is not also read as a jump.
  - `Awake` picks the first state from `LevelSession.OpenAtTitle` (test play always skips the
    title). `Restart()` reloads the same level straight into play; `NextLevel()` advances
    `LevelIndex` and reloads into play; `QuitToTitle()` resets to level 1 and opens the title;
    `ContinueAfterClear()` (Space on the clear card) picks next level, retry in test play, or
    the title after the last level. `QuitApplication()` quits (stops play mode in the editor).
    Items spawn behind the title too.
  - Holds a reference to the scene's `PlayerController` (no singleton); sets
    `PlayerController.InputEnabled` from the state (only in `Playing`). Gravity keeps applying
    while disabled.
  - Pause: `Time.timeScale = 0` while `Paused`, back to 1 on any other state and before a reload.
  - Reads `Player/Restart` (ignored at the title) and `Player/Pause` (toggles
    `Playing`/`Paused`).
  - Water check: the player's feet below `MapMetrics.WaterLevel` → spawn `Splash` at the
    surface and switch to `GameOver`. The fox keeps sinking under gravity.

### 8.1 UI

UI Toolkit: `Assets/UI/GameUI.uxml` + `GameUI.uss` (hand-written), `GameTheme.tss` (imports the
default runtime theme), `GamePanelSettings.asset` (built by `UIAssetBuilder`; scale with screen
size, 1920×1080 reference). `GameUI` (on the `UI` object with a `UIDocument`; references
`GameManager` and `PlayerController`) shows one overlay per state via the `hidden` class.
No `EventSystem` is needed; UI input comes from the Input System's default UI actions.

- **Style: minimal flat**, picked from Codex-generated mockups (voxel, soft casual, minimal).
  Inter Regular (OFL, copied from the Unity editor with its license) for all text; white text;
  dark translucent navy panels (`rgba(14, 24, 40, 0.62–0.78)`) with a 1 px white 10–14% border;
  gold only on gems. No blur (UI Toolkit has none).
- **Icons**: `GameIcon` (`[UxmlElement]`, `kind` attribute) draws flat vector icons with
  `Painter2D` in the element's USS `color`: `Gem` (three gold faces), `Clock`, `Play`,
  `Restart`, `Quit`, `Walk` (›), `Run` (»), `FoxMark` (the app icon's fox head, eyes cut out).
- **HUD** (hidden at the title): top-left pill with gem + `n / total` (bumps to 112% for 0.12 s
  on a pickup), top-center pill `LEVEL n / m` (`TEST PLAY` in test play), top-right pill with `m:ss`. Bottom-left hint row (fades out outside `Playing`):
  `» fox RUNNING` / `› fox WALKING`, `[Ctrl] Walk / Run`, `[R] Restart`, `[Esc] Pause`, with key
  caps and thin separators.
- **Title**: light dim over the live scene; fox mark, `FOX ISLAND` (120 px, letter-spaced),
  `▶ Press Start` button, `[Space] to start`, and a quiet `Quit` button.
- **Pause**: card "Paused" with Resume, Restart, Quit to Title.
- **Game Over**: card "Game Over" with `Restart (R)`.
- **Clear**: card "Clear!", divider, clock + `m:ss.s` and gem + `n / total`, then
  `▶ Next Level (Space)` (if there is one) and `Retry (R)`. On the last level the title is
  "All Clear!" with only `Back to Title (Space)`; in test play only `Retry (R)`.
- Buttons act only in the state that shows them (a hidden button can keep focus and Space
  would submit it), and focus is cleared on every state change.
- Motion: overlays fade (opacity 0.3 s; `.overlay.hidden` hides by opacity + visibility so the
  transition can run), cards scale in from 94%, buttons brighten on hover and press to 98%.
